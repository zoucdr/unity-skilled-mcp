## 技能客户端扩展（发现 → 检索 → 取定义 → 使用 → 批量执行）

对比目标项目 `com.coplaydev.unity-mcp` 后确认：本包工具覆盖已基本齐全（`batch_execute` 由服务端现有 `batch_call` 承担），真正缺口在 Skill 客户端「能看到定义却用不了」。本轮只改 JS/Python 客户端与文档，**未新增 C# 文件**，避免引入新的 Unity 编译验证负担。

- 新增 4 个双语言一致的命令：
  - `find QUERY [--kind tools|prompts|resources]`：GET 一次目录，本地按 name/uri/description/tags 大小写不敏感过滤，返回 `{kind,query,matches,count,total}`；不取详情、不走 MCP 协议。
  - `prompt NAME`：先校验 `/prompts` 目录成员，再 `prompts/get`，要求 `result.messages` 为数组。
  - `resource URI`：先校验 `/resources` 目录成员，再 `resources/read`，要求 `result.contents` 为数组。**只允许已注册 URI**——服务端 `resources/read` 兼容任意 http/file URI，直接暴露会绕过 `request` 的外发授权，这是刻意的安全边界。
  - `calls`（`--calls` / `--calls-file` / `--calls-stdin`）：输入 `[{name, arguments?}]`，顺序执行 `tools/call`、id 递增、失败即停；输出 `{steps, executed, total, stopped_at, exit_code}`，中途失败仍输出已执行步骤并用 `exit_code` 作退出码。上限复用 `max_details`（默认 32，0 不限），请求体 ≤ 65536 字节；无事务回滚，文档要求核实状态后只重放未执行步骤。
- 重构：抽出 `rpcEnvelope/rpcResult/rpcCall`、`directoryUrl/directory`，`call` 改为复用；名称/URI/关键字格式校验统一提前到 `discover()` 之前，非法输入零网络请求。
- 文档：`SKILL.md` 新增「目录检索与内容读取」「批量工具调用」两节并更新 description/退出码说明；`README.md`、`README.zh-CN.md` 命令示例与说明；`docs/index.html` 命令块、新增「检索、正文与批量」卡片、Resources/Prompts 使用方式补技能命令，并修正过时的「SKILL.md 约 5 KB」文案。
