职责分离

技能只描述「何时用、怎么传参、按什么顺序」，实际执行始终由 MCP 完成

主线程安全

发现快照在主线程构建，HTTP 线程只读快照，不触碰 Unity API 与项目设置

单一端口

发现接口与 JSON-RPC 复用同一个 HttpListener（默认 8000，可在设置中修改）

自动纳入新工具

新增工具类会自动出现在目录中；用 CapabilityTags 标注即可加入自定义分组

渐进式发现

目录 → 参数 → 执行，三步完成一次调用

1. 选目标
GET /groups — 有哪些标签组，各含多少项 GET /tools · /prompts · /resources — 名称与短说明
↓
2. 取参数
GET /tools/{name}/schema — 单个工具完整 Schema POST /capabilities/details — 一组详情
↓
3. 执行
POST /mcp — tools/call prompts/get · resources/read 保持原样

目录不带参数

描述压缩空白并截断到约 160 字符，工具目录同时给出标签，便于先筛选后读取

详情按需且有限

单次去重成员数不超过 max_details（默认 32，0 表示不限），响应硬上限 65536 字节

禁止一次拉全量

覆盖全部可用能力的选择会被拒绝：请改用标签组或明确的动态成员，单项始终允许

错误语义清晰

参数错误 400、成员未知或已禁用 404、响应过大 413，均返回结构化 JSON，不静默截断

🔎 发现与详情接口

1. 连接与目录
GET /discovery - 连接元数据、脚本语言、数量上限
GET /groups - 标签组及工具/提示词/资源计数
GET /tools - 工具名称、短说明、标签
GET /prompts - 提示词目录
GET /resources - 资源目录（uri、名称、mimeType）
2. 详情
GET /tools/{name}/schema
POST /capabilities/details
// 方式一：固定标签组
{ "tag": "hierarchy-management" }

// 方式二：本次动态成员，可混合三类
{
  "members": [
    { "kind": "tool", "name": "hierarchy_search" },
    { "kind": "prompt", "name": "实际提示词名" },
    { "kind": "resource", "uri": "file://path/to/resource.yaml" }
  ]
}
3. 命名空间别名
/mcp/tools - 与 /tools 等价
/mcp/capabilities/details - 与 /capabilities/details 等价

🧾 MCP 协议接口（兼容保留）

1. 仍然完全可用
tools/list · tools/call
prompts/list · prompts/get
resources/list · resources/read

既有 MCP 客户端无需任何改动；技能链路只是额外提供了一套更省上下文的入口。

2. 调用示例
{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "tools/call",
  "params": {
    "name": "hierarchy_search",
    "arguments": { "pattern": "Player" }
  }
}
3. 连接信息不含 MCP 地址

INI 与 /discovery 只发布 base_url、port 与各发现接口地址，不发布 /mcp 端点，避免 Agent 绕过技能直接拼协议地址。

轻量技能模块

一份 SKILL.md + 一个无依赖客户端，即可接入任意 Agent

技能目录位于 unity-package/Skills/unity3d-skill/，只说明「服务怎么连、先取什么、再取什么、参数怎么传」，不枚举 40+ 工具的参数。SKILL.md 约 5 KB，替代过去动辄数十 KB 的技能正文。

安装方式

  • 一键提示词：Unity 菜单 Window/MCP/Status → 点击「复制技能安装提示词」，把剪贴板内容粘贴到任意 Agent，即可按提示完成安装。
  • 技能路径自动解析：窗口按技能目录 .meta 的 GUID 反向查找真实磁盘路径，无论是工程内、嵌入式包还是 PackageCache 中的包都能定位。
  • 手动安装：把整个 unity3d-skill 文件夹复制到目标 Agent 的 skills 目录（如 ~/.workbuddy/skills/），目录名保持不变。

文件结构与运行方式

  • SKILL.md：唯一的入口说明，含连接、解释器选择、命令与限制。
  • scripts/unity_mcp.js：默认运行时，Node.js 18+，无第三方依赖。
  • scripts/unity_mcp.py：等价实现，Python 3.8+，命令与参数完全一致。
  • 解释器由服务启动时写入 INI 的 script_language 决定（js / python，缺字段默认 js）。

客户端命令

# 1. 核对连接（读 INI，再验证 /discovery）
node scripts/unity_mcp.js discover

# 2. 先看有哪些组和目录
node scripts/unity_mcp.js groups
node scripts/unity_mcp.js list --kind tools

# 3. 取参数：按标签组，或本次动态成员
node scripts/unity_mcp.js details --tag hierarchy-management
node scripts/unity_mcp.js details --members-file selection.json

# 4. 取单个工具 Schema 后调用
node scripts/unity_mcp.js schema hierarchy_search
node scripts/unity_mcp.js call hierarchy_search --args-file args.json

连接信息（服务启动时发布）

# ~/.unity-mcp/skill.ini
[unity3d-skilled-mcp]
base_url=http://localhost:8000
port=8000
project_path=E:/YourUnityProject
process_id=12345
updated_at=2026-10-30T02:00:00.0000000Z
script_language=js
max_details=32

启动或改端口重启都会重写该文件；最后成功启动的项目覆盖它。客户端每次命令都重新读取，不扫描端口，也不自动重试写操作。

快速开始

四步完成配置，零第三方依赖

1

导入 Unity Package

// 将 unity-package 目录导入 Unity 项目
// 或通过 Package Manager 添加 Git URL
"io.uframe.unity3d-mcp": "https://github.com/zoucdr/unity3d-mcp.git?path=/unity-package"
2

启动 MCP 服务

// 菜单 Window/MCP/Status → Start Server
// 默认端口 8000，可在设置或状态窗口中修改
// 启动成功即写入 ~/.unity-mcp/skill.ini
// 同时决定 script_language（js / python）与 max_details
3

安装技能 / 接入 MCP

// 方式一：技能（省上下文）
// 状态窗口点击「复制技能安装提示词」→ 粘贴给任意 Agent

// 方式二：直接用 MCP 客户端（能力全量）
{
  "mcpServers": {
    "unity3d-mcp": {
      "url": "http://localhost:8000"
    }
  }
}
4

开始使用

// 技能链路：先核对连接，再按需读取
node scripts/unity_mcp.js discover
node scripts/unity_mcp.js list

// 直接对话也可以
"请帮我创建一个 Cube 对象"
"分析当前场景的性能问题并提供优化建议"

Resources & Prompts 支持

目录看摘要，详情按组取，读取仍走原协议

📦

Resources 资源系统

实现 IRes 即可注册资源；目录接口只返回 uri、名称与 mimeType，详情返回注册定义，不隐式读取正文

文件访问 配置管理 按组取详情
💬

Prompts 提示词系统

实现 IPrompts 注册模板；目录给出名称与短说明，需要参数时按名称或标签组取完整定义

模板化 参数化 可扩展

🔧 Resources 配置方法

1. 实现 IRes 接口
public class ProjectTreeRes : IRes
{
    public string Url => "file://path/to/resource.yaml";
    public string Name => "project_tree";
    public string Description => "工程文件夹树型结构";
    public string MimeType => "application/yaml";
}
2. 支持的 URI 方案
file:// - 本地文件访问
http:// - HTTP 资源访问
mcp:// - MCP 自定义协议
data: - 内联数据
3. 使用方式
// 目录：只看摘要
GET /resources

// 详情：按标签组或指定 URI
POST /capabilities/details
{ "members": [{ "kind": "resource", "uri": "file://path/to/resource.yaml" }] }

// 读取正文：沿用原协议
{ "method": "resources/read", "params": { "uri": "file://path/to/resource.yaml" } }

💡 Prompts 配置方法

1. 实现 IPrompts 接口
public class TestTalkStepPrompts : IPrompts
{
    public string Name => "test_talk_step";
    public string Description => "测试对话步骤";
    public string PromptText => "请描述一个对话步骤的内容，包括角色的台词和情感。";
    public MethodKey[] Keys => new MethodKey[]
    {
        new MethodKey("step", "对话步骤", false)
        .AddExample("角色A：你好，我是A。角色B：你好，我是B。")
    };
}
2. 参数配置
Name - 提示词唯一标识符
Description - 功能描述（目录中的短说明）
PromptText - 实际提示词内容
Keys - 参数定义和示例
3. 使用方式
// 目录
GET /prompts

// 调用：沿用原协议
{ "method": "prompts/get", "params": { "name": "test_talk_step" } }
